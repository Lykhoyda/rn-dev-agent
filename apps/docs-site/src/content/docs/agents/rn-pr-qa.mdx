The PR QA agent takes a GitHub pull request, pins that head in an isolated copy, installs through rn-dev-agent, exercises the change on real targets, and reports a per-target pass/fail with screenshots and repro steps.

## Overview

| Property | Value |
|----------|-------|
| **Model** | Opus |
| **Color** | Orange |
| **Skills** | rn-workflow, rn-device-control, rn-testing, rn-debugging, capturing-proof |
| **Tools** | Bash, Read, Write, Edit, Glob, Grep, all MCP session/CDP/device tools |

## When triggered

- "QA this PR"
- "test this pull request on the simulator"
- "verify PR 812 on Android"
- "run the PR on a physical device"
- `/rn-dev-agent:qa-pr` (Claude) or `$rn-dev-agent:qa-pr` (Codex)

## Invocation constraint

Like `rn-tester`, this protocol needs MCP tools. **Do not spawn it via the Task tool** (GH #31). Run `/rn-dev-agent:qa-pr` so the parent session executes the steps.

## Protocol

1. **Resolve the PR** with `gh pr view` (URL, `owner/repo#n`, or number).
2. **Classify** the changed files. Docs-only PRs skip the device. Plugin MCP/device changes run against the workspace test-app (or the declared candidate app), never against the plugin checkout as Metro's serving root.
3. **Pin the head** in a disposable git worktree. Never mutate the primary checkout.
4. **Inventory** through `rn-workflow` steps 0–2, then `rn_session(action="status")`. `device_list` diagnoses; it does not choose.
5. **Per selected target** (`ios`, `android`, `device`, or `all`): exact `bind_device` → reversible integration → managed `<pm> run ios|android` from the app root → `pin_dev_client` → dev menu disabled and hidden (no gear) → feature proof, user path only: usable screen, recorded path, saved or reused Maestro action, walk back to the first screen as a user before each later off-camera rehearsal and the take, `device_record` start before the on-camera `cdp_run_action` proof replay, validation.
6. **Cleanup** in reverse: runner close → `stop_metro` → `restore_integration` → `release`.
7. **Report.** The public GitHub comment is for a human reviewer of the feature that was built, not a plugin log. It carries one verdict: FAIL if any tested platform failed, PASS only if every requested platform that ran passed, plus one plain sentence per platform not tested ("Android was not requested." / "Android was not available."). Missing hardware is SKIP, not FAIL; the exact remaining setup and the per-target table are in-session only. A docs-only or all-SKIP run posts the same human-shaped comment with `Verdict: SKIP`, no video and no SKIP table. Host screenshots and videos with `gh pr comment --attach`, video first, then, when a screenshot was attached, rewrite screenshots to `<img … width="390">`. Attachments are not required when there is nothing to attach. Once the public comment exists, if the PR has `needs-qa`, run `gh pr edit "<pr-url>" --remove-label needs-qa`. A missing label is not FAIL. A stale-head FAIL comment and a SKIP comment still count; a run that never posted leaves the label.

## Circuit breaker

After 3 failures of the same category on one target, that target stops. Do not switch devices mid-target.

## Safety

- No `clearState: true` against Expo Dev Client
- No simulator erase / `pm clear`
- Never steal a live device claim
- Never use raw `xcrun simctl` / `adb` for taps or screenshots
