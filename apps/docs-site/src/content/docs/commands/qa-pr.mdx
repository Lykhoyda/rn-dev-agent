Device-test a GitHub pull request. Pins the PR head in an isolated copy, installs through the rn-dev-agent session, exercises the change, and reports pass/fail with repro steps and screenshots.

## Usage

```
Claude: /rn-dev-agent:qa-pr <PR URL or number> [--platform ios|android|device|all]
Codex:  $rn-dev-agent:qa-pr <PR URL or number> [ios|android|device|all]
```

Default platform is `all` — every target that can be proven present. A requested target that is not on the machine is **SKIP** with the setup gap, not FAIL.

## Examples

```
/rn-dev-agent:qa-pr 812
/rn-dev-agent:qa-pr https://github.com/acme/app/pull/42 --platform ios
/rn-dev-agent:qa-pr 42 --platform device
```

## What it does

| Step | What happens |
|------|-------------|
| 1 | Fetch the PR with `gh pr view` |
| 2 | Classify app-facing vs docs-only vs plugin-under-test-app |
| 3 | Pin the head SHA in a disposable git worktree |
| 4 | Establish the [run-workflow](../run-workflow/) operating sequence |
| 5 | Bind one exact device, apply integration, run the managed package script |
| 6 | Feature proof (user path only): dev menu disabled and hidden with no gear, usable screen, real path recorded, action reused (proof replay, no writes) or saved without `launchApp`, first rehearsal of a reused action from its first route (walk there as a user if the attached screen is not that route, or FAIL at the step that cannot), walk back to the first screen off camera as a user (no `cdp_navigate`, no deep link) before a saved action's first rehearsal, a repeat rehearsal, and the take, off-camera rehearsal, no runtime reset or relaunch under the recorder, video started before the runner, on-camera `cdp_run_action` proof replay, validation |
| 7 | Reverse cleanup and a GitHub comment at the live head with the video first, then `needs-qa` removed when present |

## Output

- One public verdict for the PR URL + head SHA: `FAIL` if any tested platform failed, `PASS` only if every requested platform that ran passed, plus one plain sentence per platform not tested ("Android was not requested." / "Android was not available.")
- A docs-only or all-SKIP run posts the same human-shaped comment with `Verdict: SKIP`, no video and no SKIP table
- In-session only: the per-target table (screenshot + video, route, error count)
- Repro steps a human can follow
- A `gh pr comment` with `--attach` for every screenshot and video, then,
  when a screenshot was attached, screenshot markdown rewritten to
  `<img … width="390">` so they are reasonably large on GitHub. Videos stay
  as GitHub player embeds and are the primary proof. Attachments are not
  required when there is nothing to attach. Never leave unhosted local
  paths as the reviewer-visible proof. The public GitHub comment is for a human reviewer of the feature that was built, not a plugin log.
  Once the public comment exists, if the PR has `needs-qa`, run `gh pr edit "<pr-url>" --remove-label needs-qa`. A missing label is not FAIL.
  A stale-head FAIL comment and a SKIP comment still count; a run that never posted leaves the label.

## Prerequisites

- `gh` ≥ 2.99 with push access (`gh pr comment --help` lists `--attach`)
- Project onboarded (`/rn-dev-agent:setup` or `$rn-dev-agent:setup`)
- iOS: Xcode + a simulator runtime
- Android emulator: Android SDK + AVD
- Physical: USB debugging, exclusive claim, exact serial
- Pin-cache maestro-runner `>= 1.1.27`
- Expo dev client: floating dev-menu gear turned off at build time (`EXDevMenuShowFloatingActionButton` = `false`); a visible gear is FAIL

This command runs the [`rn-pr-qa`](../../agents/rn-pr-qa/) protocol inline in the parent session (GH #31).
