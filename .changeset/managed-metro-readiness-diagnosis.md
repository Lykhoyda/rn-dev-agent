Make the managed-Metro startup refusal truthful and give a cold start room to listen (GH #992). When the readiness deadline expires, `METRO_START_UNAVAILABLE` now reports the launcher state and the Metro log tail as they were before the supervisor's own group SIGTERM, and names why the deadline expired (`readiness deadline N ms expired: listener absent … probes, probe unknown …, unowned listener …`). Previously both were read after the kill, so the loader's post-kill `EPIPE: broken pipe, write` and `launcher signal SIGTERM` — consequences of the cleanup — were presented as the cause. A cleanup that cannot prove the port free (`METRO_START_CLEANUP_UNPROVEN`) carries the same pre-kill launcher state and probe tallies. The readiness budget is raised from 20 s to a 90 s default (provisional pending a cold-start measurement) and becomes the one per-project setting `.rn-agent/config.json` → `metro.readinessTimeoutMs` (integer, 1000–600000); a malformed value or a non-object `metro` section refuses with `METRO_READINESS_TIMEOUT_INVALID` instead of silently using the default. The generated adapter's `ensure-metro` SIGKILL bound is derived at runtime from that budget plus a 25 s cleanup margin, floored at today's 120 s, so a configured value cannot be truncated into `SESSION_CLI_TIMEOUT`. At the 90 s default the derived caller timeout remains 120000 ms. The loop still returns the instant Metro is proven and still exits early when the launcher dies, and the setting is a timeout only — it never gates or relaxes any authority proof. The pre-start `no-install-receipt` advisory is unchanged: it is expected on a session's first build and is not an independent failure.
